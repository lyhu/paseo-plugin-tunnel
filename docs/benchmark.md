# Paseo HTTP Tunnel 性能基准与压测报告

本文档记录 Paseo HTTP Tunnel 在 0.2.0 版本引入**预连接通道池**与**ACK 滑动窗口**后的性能测试对比、基准数据与复现指南。

---

## 1. 核心结论与收益摘要

通过在插件内部实施传输层优化，在不修改 Paseo 宿主、Relay 中继协议及上游服务的前提下，显著降低了建连抖动与流式卡顿：

```text
┌────────────────────────────────────────────────────────────────────────┐
│  • 首包头到达耗时 (TTFB): 442.69 ms ──> 82.44 ms  (🔻 降幅 81.4%)        │
│  • 1 MiB 完整传输耗时:   2416.57 ms ──> 1348.10 ms (🔻 降幅 44.2%)       │
│  • SSE 首个数据帧到达:     427.99 ms ──> 101.57 ms  (🔻 降幅 76.3%)       │
│  • SSE 最大数据块间隔:     150.07 ms ──>  83.57 ms  (🔻 降幅 44.3%)       │
└────────────────────────────────────────────────────────────────────────┘
```

> [!NOTE]
> **设计取向说明**：针对私有大模型与 SSE 流式生成服务，系统**未引入透明响应缓存**。大模型推理的动态生成语义、上下文隔离以及调用方计费逻辑决定了透明代理层绝不能随意缓存数据。

## 2. 固定负载基准测试 (Synthetic Benchmark)

### 2.1 测试环境与基线定义

- **测试日期**：2026-09-05
- **对比基线**：Git 提交 `75b3017`（优化前原始实现）对比当前优化实现。
- **网络拓扑**：Ingress、Egress 及模拟服务部署于同台 macOS 测试机，流量强制经过公网真实 TLS Relay 中继；直连对照组直接访问 Loopback 目标端口。
- **采样方法**：每组负载交替运行 6 轮测试，剔除首次预热轮次后取后 5 轮各项指标的中位数（Median）。每轮开始前等待 1 秒，使预连接有机会就绪；结果代表有预连接可用时的表现，不代表长时间空闲后的首次请求。

### 2.2 核心指标对比

| 负载场景与指标项 | 基线耗时 (优化前) | 优化后耗时 | 性能提升 |
| :--- | :---: | :---: | :---: |
| **256 B 响应头到达 (TTFB)** | 442.69 ms | **82.44 ms** | **-81.4%** |
| **1 MiB 完整传输耗时** | 2416.57 ms | **1348.10 ms** | **-44.2%** |
| **SSE 首个 Body 块到达** | 427.99 ms | **101.57 ms** | **-76.3%** |
| **SSE 完整数据流耗时** | 1778.48 ms | **1369.78 ms** | **-23.0%** |
| **SSE 最大收包间隔 (抖动)** | 150.07 ms | **83.57 ms** | **-44.3%** |

*注：SSE 目标测试源固定每 10 ms 发送一个事件，共计 100 个事件（23,290 字节）。原始采样数据参见 [基线数据](../benchmark/results/transport-before.json) 与 [优化后数据](../benchmark/results/transport-after.json)。*

这是单机、单 Relay、少量顺序样本，不能推导其他部署的固定提速比例。两项优化同时启用，不能单独归因各项收益；HTTP 数据块间隔不等同于 SSE 事件间隔，也不能单独证明中间层存在缓冲。

## 3. 大模型推理流式对比 (LLM Service Benchmark)

优化前从同一客户端对 Nginx 与 Tunnel 各交替测量 2 次。服务提供者确认两条路径使用同一后端，但 model 别名和 thinking/text 表达不同：

| 评估指标 | Nginx 直连代理 | Tunnel (优化前) |
| :--- | :---: | :---: |
| **首次生成响应 (Thinking/Text)** | 0.39 – 0.44 s | 2.15 – 2.26 s |
| **首次正文到达 (First Text)** | 2.93 – 3.35 s | 2.15 – 2.26 s |
| **生成阶段平均速率 (Token/s)** | 108 – 109 tok/s | 105 – 106 tok/s |
| **最大流式事件间隔** | 0.52 – 0.59 s | 0.79 – 1.04 s |

> **数据分析**：本组样本的输出阶段平均速率接近，但样本量不足以证明不存在吞吐瓶颈。Nginx 返回独立 thinking delta，Tunnel 该次上游响应只返回 text delta，生成长度和停止原因也不同；首次输出差异不能直接视为代理开销。速率由上游报告的输出 token 数除以首末输出事件时间差估算，不是精确解码速率。

## 4. 生产环境部署实测复验

在跨主机实际部署环境中（本地 macOS 运行 Egress，远程 Linux 服务器运行 Ingress，通过公网 Relay 互联），使用相同模型别名进行连续采样：

| 采样轮次 | 首字耗时 (TTFT) | 完整响应耗时 | 输出 Token | 最大事件间隔 |
| :--- | :---: | :---: | :---: | :---: |
| **更新前基线** | 2078 ms | 9856 ms | 757 | 742 ms |
| **更新后首轮** | 2644 ms | 10477 ms | 589 | 612 ms |
| **更新后连续请求** | **535 ms** | **8104 ms** | 754 | 709 ms |

*完整脱敏记录参见 [实测请求样本](../benchmark/results/model-tunnel.json)。*

**结果解读**：这次连续请求的首次输出较基线降低约 **74%**，但更新后首轮未改善。本次未采集实际业务请求的预连接命中计数，不能确认命中或分摊握手、排队与生成耗时；样本量不足以声称稳定的业务提速比例，约 0.7 秒的最大事件间隔仍存在。

## 5. 基准测试复现指南

### 5.1 本地快速复现（内置 workerd Relay）

在仓库根目录下运行自动化测试脚本，默认启动本地隔离的 workerd Relay，无需预先安装 Paseo：

```bash
# 安装依赖
npm ci

# 运行传输层基准测试
npm run benchmark:transport
```

### 5.2 使用自定义网络 Relay

```bash
# 环境变量指定中继地址（默认开启 TLS）
BENCH_RELAY_ENDPOINT='relay.example.com:443' npm run benchmark:transport

# 禁用预连接对比握手耗时
BENCH_PRECONNECT=0 BENCH_RELAY_ENDPOINT='relay.example.com:443' npm run benchmark:transport
```

对比其他源码版本时，在独立目录安装该版本的依赖，设置 `BENCH_SOURCE_ROOT=/absolute/path/to/checkout`，仍从当前仓库运行相同脚本，以保持负载和采样方法一致。

### 5.3 大模型推理 SSE 测试

```bash
export BENCH_URL='http://127.0.0.1:1380/v1/messages'
export BENCH_MODEL='your-model'
export BENCH_LABEL='tunnel'
export BENCH_API_KEY='your-api-key'
export BENCH_ACCESS_TOKEN='your-tunnel-access-token'

# 执行压测
npm run benchmark:sse
```

## 6. 单元与回归测试验证

确保流控滑动窗口与预连接池在边界条件下的正确性：

```bash
# 运行传输层与预连接单元测试
npm run test:file -- src/server/performance.test.ts

# 运行 SSE 流解析容错测试
node --test benchmark/sse-parser.test.mjs
```

**测试覆盖项**：
- **流控边界**：阻塞 8 个 ACK 仅释放首块，断言第 9 个数据块正常发送。
- **池生命周期**：验证并发上限、认证隔离、空闲 30s 自动过期及进程退出清理。
- **协议健壮性**：覆盖 SSE 数据帧任意拆分、CRLF 跨块切分及异常取消流程。

# Paseo HTTP Tunnel v0.3.0 Release Notes

Paseo HTTP Tunnel **v0.3.0** migrates the plugin to the **Paseo 0.8 plugin runtime**. It is a breaking release for the host side: the plugin now requires Paseo CLI and daemon **0.8.0 or newer**.

---

## Key Highlights

- **Paseo 0.8 Runtime Entries**: The single `index.ts` entry is replaced by `index.server.ts` (daemon subprocess) and `index.client.tsx` (Paseo app), matching Paseo 0.8's per-runtime entry model.
- **Compile Boundary Layout**: Source modules now live in `client/`, `server/`, and `shared/`, and the `*.client` / `*.server` / `*.shared` filename suffixes are gone. Each bundle is built only from its matching directory.
- **Runtime-Neutral Contracts**: RPC contracts and Zod schemas import from the `@getpaseo/plugin` root, client hooks and surface props from `@getpaseo/plugin/client`.
- **Web-Only Globals Isolated**: Browser APIs are confined to `client/web.ts` behind `Platform.OS` checks, and the DOM lib is no longer part of the typecheck configuration.
- **Explicit Host Requirement**: `paseo-plugin.json` declares `requirements.paseo: ">=0.8.0"`, so older hosts refuse the plugin with Paseo's own upgrade diagnostic.

---

## Compatibility

| Component | Requirement |
| :--- | :--- |
| Paseo CLI & daemon | **0.8.0 or newer** |
| Node.js (daemon process) | 22 or newer |
| Plugin SDK | `@getpaseo/plugin`, `@getpaseo/client`, `@getpaseo/relay` **0.8.0** |

> [!IMPORTANT]
> Paseo 0.7.x cannot load this version. Source modules are no longer allowed at the plugin root, and the daemon refuses a manifest that does not declare `requirements.paseo` as `>=0.8.0`.

---

## Installation and Upgrade

### Fresh Installation (Pinned Tag)

```bash
paseo plugin install lyhu/paseo-plugin-tunnel --ref v0.3.0
```

### Upgrade Existing Installation (Tracking `main`)

```bash
paseo plugin update http-tunnel
paseo plugin status http-tunnel
```

> [!NOTE]
> Existing configuration and keys at `$PASEO_HOME/tunnel/config.json` are fully preserved. The upgrade requires a Paseo 0.8.0+ host; updating reloads the plugin and can interrupt active requests, but does not require restarting the primary Paseo daemon.

---

## Verification Status

- Typecheck, Biome lint, local server/client bundling, and the unit and Relay-backed end-to-end suites pass on the migrated layout.
- The recorded real-host verification baseline still comes from Paseo 0.7.2. A full host regression on Paseo 0.8.0 is tracked as pending work in [VERIFICATION.md](https://github.com/lyhu/paseo-plugin-tunnel/blob/v0.3.0/VERIFICATION.md).

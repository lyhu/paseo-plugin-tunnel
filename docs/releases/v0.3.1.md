# Paseo HTTP Tunnel v0.3.1 Release Notes

Paseo HTTP Tunnel **v0.3.1** is a fix release for the v0.3.0 Paseo 0.8 migration. It restores Git installation and update on hosts running npm 10.

---

## What Was Fixed

- **Manifest `build` failed on npm 10 hosts.** `package-lock.json` had been regenerated by npm 11, which omits platform-specific optional dependencies (the `@esbuild/*` binaries pulled in through `vitest`). npm 10 treats that lock file as out of sync and aborts `npm ci` with:

  ```text
  npm error `npm ci` can only install packages when your package.json and
  npm error package-lock.json or npm-shrinkwrap.json are in sync.
  ```

  Because the manifest runs `npm ci --omit=dev` before compiling, Git installs and updates were rejected on those hosts while npm 11 hosts were unaffected. The lock file is regenerated with npm 10 and verified against both npm 10.8 and npm 11.19.

---

## Compatibility

| Component | Requirement |
| :--- | :--- |
| Paseo CLI & daemon | **0.8.0 or newer** |
| Node.js (daemon process) | 22 or newer |
| npm (daemon host, for the manifest `build`) | 10 or newer |
| Plugin SDK | `@getpaseo/plugin`, `@getpaseo/client`, `@getpaseo/relay` **0.8.0** |

---

## Installation and Upgrade

### Fresh Installation (Pinned Tag)

```bash
paseo plugin install lyhu/paseo-plugin-tunnel --ref v0.3.1
```

### Upgrade Existing Installation (Tracking `main`)

```bash
paseo plugin update http-tunnel
paseo plugin status http-tunnel
```

> [!NOTE]
> Existing configuration and keys at `$PASEO_HOME/tunnel/config.json` are preserved. Updating reloads the plugin and can interrupt active requests; it does not require restarting the primary Paseo daemon.
